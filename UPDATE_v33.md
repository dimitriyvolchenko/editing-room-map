# Editing Room 33.0.0-bookmarks

## Бейджи

Твои данные → Сохранение между устройствами → Мои задачи и закладка.

«Показывать бейджи моих задач» включает число на карточках и на вкладках Mobile / DaVinci. Считаются только добавленные пользователем «Свои шаги»: 1, 2, 3 и далее. Стандартные шаги не учитываются. По умолчанию считаются все свои задачи, в том числе выполненные. «Считать только невыполненные» меняет это правило. Удаление задачи уменьшает счётчик; при нуле бейдж скрывается.

«Показывать это число на иконке приложения» передаёт системе суммарное число по двум маршрутам через Badging API. На iPhone / iPad приложение нужно открыть с экрана «Домой», а затем нажать «Разрешить бейдж на иконке» и дать системное разрешение уведомлений. Разрешение запрашивается только по нажатию, никогда автоматически. Цифра может быть скрыта настройками уведомлений устройства. В обычной вкладке или неподдерживаемом браузере остаются бейджи внутри карты.

Push-сервер не добавлен: закрытое приложение не получает новые числа с других устройств в фоне. После запуска и синхронизации счётчик пересчитывается. Приложение не отправляет push-уведомления.

## Закладка

Контур ленты вверху карточки или кнопка «Поставить закладку» внутри карточки устанавливает закладку. Повторное нажатие снимает её. В каждом маршруте может быть одна закладка. Лента и сохранённая карточка выделены тонким красным контуром без красной заливки.

«При новом запуске открывать последнюю поставленную закладку» включено по умолчанию. Приложение выбирает нужный маршрут, раскрывает карточку и прокручивает к ней. Просмотр других карточек, отметки выполнения и переключение вкладок больше не двигают явную закладку. Завершённая задача также может оставаться закладкой.

При первом переходе с v32 последняя старая точка продолжения (cursor) принимается за начальную закладку: старая версия не различала её и обычную навигацию. После обновления поставь явную закладку на нужной карточке. При отключённом возврате сохраняется обычная навигация и положение прокрутки.

## Локальный прогресс, онлайн и без сети

Прежний ключ editing-room.map.v30 сохранён. Галочки, свои задачи, заметки и цели записываются на устройство при изменениях. Новые настройки и явные закладки находятся в ui и включены в обычный экспорт/импорт JSON. Они остаются локальными, не навязываются другому устройству при GitHub-синхронизации. Облачный механизм v32 и его формат не изменены; токен по-прежнему хранится отдельно.

Для повторного запуска опубликованного сайта без сети добавлен sw.js рядом с index.html. Он сохраняет только HTML-оболочку приложения, а не прогресс, ключи или GitHub API. Один раз открой сайт онлайн и дождись «Готово для запуска без сети». Есть кнопка «Сохранить для работы без сети». До появления этого статуса офлайн-запуск не обещается. Браузер может удалить данные сайта при очистке; отдельный резервный JSON остаётся необходимым.

## Принудительное обновление

Твои данные → Сохранение между устройствами → Обновление приложения → Принудительно обновить.

Кнопка создаёт защитную локальную копию, проверяет свежую HTML-страницу, обновляет офлайн-копию и открывает новую версию. Прогресс, токен, иконки и явные закладки не очищаются. Без сети, при ошибке сервера, неверном HTML или проблеме локального сохранения перезагрузка отменяется. При последующем запуске адрес с параметром er_update также может открываться офлайн. Кэши других приложений не удаляются.

Для онлайн-работы достаточно index.html. Для офлайн-перезапуска опубликованного сайта загрузите также sw.js в ту же папку. ZIP содержит оба файла и исходники. Не удаляйте данные Safari или старый установленный ярлык до проверки прогресса в новом.

## Проверки и границы

Исходный index.html v32 сверён с репозиторием: blob 8f826ed31e20b1853f331bc3b265cf36b58fa919. Встроенный app-data и байты трёх увеличенных иконок не менялись. Сохранены 170 действий и 916 базовых шагов.

Пройдены 15 тестов объединения прогресса, 12 тестов service worker в Node с имитацией сети/CacheStorage и 33 браузерные проверки взаимодействий и ширин 320/390/768/1440. Браузер: Chromium; хранилище, адрес, запросы и системный бейдж имитировались, поскольку навигация тестового браузера ограничена средой. В финальном прогоне тяжёлые встроенные картинки заменялись только в тестовой копии; изображения поставляемого приложения не изменены. Снимки интерфейса дополнительно получены с оригинальными картинками.

Это не физический тест iPhone, не реальная проверка системного бейджа и не холодный офлайн-запуск на телефоне. Существующие проверки синхронизации не заменяют проверку с пользовательским ключом. Сборка повторяется побайтно, исходные материалы не пересобираются и не исправляются.
