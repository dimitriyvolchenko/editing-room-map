# Editing Room 32.0.0-sync

Обновление сохраняет существующий ключ editing-room.map.v30, исходные инструкции, оба маршрута и три увеличенные иконки. Для работы нужен один index.html; sync/core.js и sync/integration.js встроены в него при сборке.

## Подключение на каждом устройстве

Открой «Твои данные» → «Сохранение между устройствами» → «Настройки GitHub».

Предложенные настройки: репозиторий dimitriyvolchenko/planner-data, ветка main, отдельный файл editing-room-map-progress.json. Введи собственный fine-grained GitHub token с доступом к выбранному репозиторию и разрешением Contents: Read and write. Нажми «Подключить и синхронизировать». Первое создание файла требует подтверждения. На остальных устройствах используй тот же путь.

Ключ не встроен в сайт и не передаётся в файл прогресса или резервный JSON. По умолчанию он хранится только в текущей вкладке; опция «Запомнить ключ» сохраняет его в браузере. Скрипты того же веб-источника потенциально могут прочитать сохранённый ключ: ограничь доступ одним репозиторием. Не присылай ключ в чат и не помещай в исходный код.

До подключения GitHub работает локальное сохранение. Публикация обновления сама по себе не подключает браузер к облачному прогрессу. Публичный репозиторий для заметок допускается только с отдельным явным разрешением в настройках.

## Сохранение и конфликты

Каждое изменение сначала сохраняется локально. Автосинхронизация запускается после паузы во вводе, возвращения связи или возвращения в приложение; открытая видимая страница также проверяет данные примерно раз в минуту.

Переносятся отметки, заметки, цели сессии, поля исходников и собственные шаги обоих маршрутов. Иконка, прокрутка и выбранная вкладка остаются локальными. Трёхстороннее сравнение использует последнюю согласованную версию: независимые изменения объединяются, снятые галочки и удалённые шаги учитываются. Разные редакции одного поля требуют выбора. При конфликте SHA GitHub файл читается повторно, а изменения объединяются заново.

Без сети неотправленная работа остаётся на устройстве. Закрытое приложение не обязано отправлять её в фоне: после возвращения сети открой сайт и проверь статус. Другой формат прогресса, неизвестные шаги или исчезновение ранее сохранённого файла останавливают запись вместо перезаписи. Существующие файлы других приложений не изменяются.

## Принудительное обновление

«Твои данные» → «Обновление приложения» → «Принудительно обновить».

Кнопка сохраняет работу, создаёт защитную локальную копию, проверяет новую HTML-страницу и перезагружает сайт с новым параметром адреса. Она не очищает localStorage, IndexedDB или данные других приложений. При отсутствии сети или ошибке проверки приложение остаётся открытым. Это не очистка всех данных Safari.

«Защитная копия» скачивает последний защитный снимок, который можно восстановить через «Импорт JSON». Перед очисткой браузера всегда скачивай обычную резервную копию: защитные снимки хранятся в том же браузере и также исчезнут при удалении данных сайта.

## Анализ и проверки

Изучены sync-core.js и README_RU.md проекта study, а также интерфейс GitHub и сравнение с согласованной версией в pannerformanytasks/index.html. Механизм адаптирован под Editing Room; это не перенос всего кода другого приложения.

Пройдены 15 модульных тестов и 15 браузерных/интеграционных сценариев, включая независимые изменения, снятие галочек, конфликт заметок, повтор после SHA-конфликта, ввод во время отправки, сбой сети, защиту чужого формата, отсутствие ключа в экспорте, принудительное обновление и ширины 320/390/768/1440 пикселей.

Браузерная проверка выполнялась в Chromium с имитацией GitHub API, хранилищ и перезагрузки. Это не физический iPhone и не синхронизация с реальным пользовательским ключом. Отдельно выполнены реальная сборка GitHub Actions и публикация Pages.

Разработка: node tests/merge.test.cjs; python3 tools/build_sync.py. Сборка проверяет синтаксис JavaScript и неизменность исходного app-data.
